# Fossil: documentation review

Reviewed 22 October 2026 from the official Fossil documentation at fossil-scm.org only (quickstart, concepts, backup, file format, import/export, shunning, self-hosting, FAQ, release notes, home page). Latest release listed: 2.28 (2026-03-11); the release notes list 2.29 as pending, and the home page footer says it was generated by Fossil 2.29. Licence: 2-clause BSD, per the home page. The release notes page was read only to character 100000 of 128092, so the version statement rests on the part read.

**Evidence class:** vendor or maintainer declaration. Nothing here was run or tested, so it cannot establish a Pass or a Fail under v3.1.

## What the documentation says

**Storage and access (E1, E3)**
- A repository is "a single disk file" that the docs describe as SQLite-backed. The file also holds sensitive data, and the quickstart suggests `fossil scrub` before sharing it. [quickstart](https://fossil-scm.org/home/doc/trunk/www/quickstart.wiki), [home](https://fossil-scm.org/home/doc/trunk/www/index.wiki)
- The artifact format (manifests, wiki, tickets, attachments, forum) is specified in detail. Artifacts are stored as delta- and zlib-compressed blobs in SQLite, which the page calls "an implementation detail" that "might change". [file format](https://fossil-scm.org/home/doc/trunk/www/fileformat.wiki)
- The page says the artifact format, not the on-disk layout, is "intended to be enduring". Whether a third-party tool can read the repository file was not found in the docs.
- `fossil ui` starts a local web server bound to 127.0.0.1. [quickstart](https://fossil-scm.org/home/doc/trunk/www/quickstart.wiki)

**Exit and migration (E2)**
- Git export: `fossil export --git ... | git fast-import`; import is the reverse. Tickets, wiki and events are not exported, because "Git does not understand those concepts". Handling of private content is not stated. [import/export](https://fossil-scm.org/home/doc/trunk/www/inout.wiki)
- Older PowerShell may fail on large repositories when piping; the page recommends WSL or Git for Windows. [import/export](https://fossil-scm.org/home/doc/trunk/www/inout.wiki)
- A clone is a full copy of what the user may see, but not everything (see Recovery). The FAQ only points to the import/export page and gives no detail. [FAQ](https://fossil-scm.org/home/doc/trunk/www/faq.wiki)

**Recovery (E3)**
- A clone "may serve as a suitable backup", but omits: sensitive user data unless logged in with Setup capability, most configuration (skins, alerts, ticket customisation), private branches, shunned artifacts, and unversioned files unless requested. [backup](https://fossil-scm.org/home/doc/trunk/www/backup.md)
- Backup methods given: scripted `fossil sync --unversioned`, `fossil configuration pull all`, `fossil rebuild` (needs Setup capability), or `fossil backup` over SSH for SQL-level copies including private branches. [backup](https://fossil-scm.org/home/doc/trunk/www/backup.md)
- Autosync is not transitive, so a backup of a stale server is stale. Restore should use `fossil sql`, not an arbitrary `sqlite3`, because the dump may use features other versions lack. [backup](https://fossil-scm.org/home/doc/trunk/www/backup.md)
- Upgrade: replace the executable; `fossil all rebuild` "might" be needed afterwards. Cross-version repository compatibility is not described. 2.28 notes, as read, mention no schema change. [concepts](https://fossil-scm.org/home/doc/trunk/www/concepts.wiki), [changes](https://fossil-scm.org/home/doc/trunk/www/changes.wiki)

**Continuing authority (E4) and dependencies**
- Single self-contained executable; sync over HTTPS or SSH; no mandatory hosted service. Autosync is on by default. [home](https://fossil-scm.org/home/doc/trunk/www/index.wiki), [quickstart](https://fossil-scm.org/home/doc/trunk/www/quickstart.wiki)
- Fossil self-hosts on three synchronised servers since 2007; one also mirrors to GitHub. The page does not mention telemetry or update checks. [self-hosting](https://fossil-scm.org/home/doc/trunk/www/selfhost.wiki)
- Contributors assign joint copyright to Hwaci under a paper-signed agreement. [copyright release](https://fossil-scm.org/home/doc/trunk/www/copyright-release.html)
- The history page says the SQLite architect "is still the top committer", with other contributors. No succession or governance statement was found in the docs. [history](https://fossil-scm.org/home/doc/trunk/www/history.md)

**Consequential operations (E5)**
- `fossil undo` reverses merge or update changes in the checkout only, single level, and not after check-in. [quickstart](https://fossil-scm.org/home/doc/trunk/www/quickstart.wiki)
- Shunning blocks artifacts from sync; content is physically removed at the next `rebuild`. The page does not describe reversing it. Shun lists are local unless copied, and pulls accept them by default unless auto-shun is off. Fossil prefers hiding or amending to deleting. [shunning](https://fossil-scm.org/home/doc/trunk/www/shunning.wiki)
- Moving or deleting a repository file breaks linked checkouts. [concepts](https://fossil-scm.org/home/doc/trunk/www/concepts.wiki)
- Replicating alert settings can send duplicate emails; pushing project config can merge two repositories. [backup](https://fossil-scm.org/home/doc/trunk/www/backup.md)
